# 投资产品经理参考

## 事实源优先级

1. `configs/symbols.json`：标的、权重、角色、策略参数
2. `backend/app/strategies/`：估值、趋势、止盈和合成公式
3. `backend/app/services/engine.py`：信号编排、金额与状态
4. `frontend/src/lib/api.ts`：前后端契约
5. `PRD.md`：产品口径；与代码不一致时必须修正
6. `.cursor/skills/a-share-dca-fund-manager/`：投资解读方法

## 当前用户主任务

用户打开产品时，应按顺序回答：

1. 信号日期是否有效、数据是否新鲜？
2. 今天是不是定投执行日？
3. 今天买入、暂停或减仓什么？
4. 金额/比例是多少？
5. 为什么？估值、均线、硬否决、止盈各贡献什么？
6. 下一次需要做什么？

## 当前公式

### 买入合成

`final_mult = clip(w_val × m_val + w_trend × m_trend, 0, max_mult)`

- 核心：70% 估值 + 30% 趋势
- 成长：55% 估值 + 45% 趋势
- 硬否决优先于加权平均
- 超跌解封使用明确的小额倍数
- 止盈不进入买入合成

### 金额

`amount = period_amount × target_weight × final_mult`

之后可经过现金池和预算上限缩放。非执行日买入金额为 0，但止盈每日检查。

## 产品一致性检查

- [ ] 标的、ETF 代码和目标权重与配置一致
- [ ] 页面明确 T-1，不暗示实时信号
- [ ] 倍数与金额不混用
- [ ] 止盈显示减仓比例，不显示成买入倍数
- [ ] 硬否决的开关后果明确
- [ ] 代理估值标明口径
- [ ] 数据缺失/过期时安全暂停并说明
- [ ] 全局设置与 per-symbol 参数没有双轨
- [ ] 核心/成长模板未被无理由拆成五套
- [ ] 网格/再平衡没有误接回主引擎

## 指标建议

### 核心指标

- **执行清晰率**：无需展开帮助即可正确回答今日动作的用户占比
- **解释触达率**：查看策略 reason / 计算依据的用户占比
- **执行完成率**：执行日查看并确认操作的比例（若产品提供确认）

### 护栏指标

- 数据过期仍展示买入建议次数：必须为 0
- 金额与后端计算不一致次数：必须为 0
- 同步失败导致整站不可用次数
- 用户因“倍数/减仓比例/执行日”产生的误解反馈

## 新策略评审示例

用户提出加入 RSI：

1. RSI 与现有趋势因子高度相关，独立信息弱。
2. 若只是再次降频，会与均线职责重叠。
3. 增加阈值与页面解释成本，存在过拟合风险。
4. 默认结论：暂不进入主策略；可作为研究面板，不影响金额。

用户提出展示“为什么暂停”：

1. 直接降低执行不确定性。
2. 使用现有 `reason`，实现成本低。
3. 不改变策略风险。
4. 默认结论：P1，优先实施。
